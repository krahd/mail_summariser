# Isolated synthetic onboarding

This bounded first version lets a person practise the current browser workflow without configuring any account. It demonstrates evidence-led triage and reversible actions. It does not establish real-account acceptance, privacy/security readiness or commercial demand.

## Start

From a source checkout with Python 3.11 or later:

```sh
python -m venv .venv
# Activate the virtual environment using your operating system's normal command.
python -m pip install -e .
python scripts/run_demo.py
```

Open `http://127.0.0.1:8767`. Use `--port 8768` if that port is occupied. The single process serves the existing `webapp/` and backend together. Stop with Ctrl+C. No provider, email account or model installation is needed. Installing dependencies still requires normal package-registry connectivity.

Do not expose this server to the network or run it behind a public proxy. The demo is local and single-process. It is not an authenticated hosting product.

## A five-minute acceptance path

1. Read the first-run guide. Eight fictional messages are already indexed; six are unread.
2. Inspect a triage candidate, its heuristic reasons and its underlying message. Buckets may overlap; they do not prove that a reply or payment is due.
3. Select **Summarise** on a bucket. Read the local excerpt digest and message evidence in **Review & Act**. The digest is explicitly not generated by AI.
4. Select mark-read, tag or archive. **Preview Selected Actions** shows every affected subject, current state and planned state. Cancel leaves the inbox unchanged.
5. With **Simulate only** checked, confirm a preview. This records a dry run and leaves all messages unchanged.
6. Uncheck **Simulate only** to enable fictional-message changes. Preview again, apply, then undo from the toast or **Log**. Archive is a folder move; it is not deletion. Triage/index counts refresh after changes and undo.
7. Reset the sample inbox, or stop the process. Reset asks before clearing demo digests and undo history and restores safe mode.

**Rebuild sample index** is a visible, non-destructive recovery control. It preserves messages, digests, logs and remaining undo history. A completed apply or undo whose index refresh failed returns its completed result plus an explicit warning; it is not re-queued or automatically repeated. Stale index reads fail explicitly until rebuilding succeeds. **Reload demo** retries view loading only.

If a request fails, the previous digest remains available. A cancelled or superseded digest cannot replace it later. Cancelled/changed/navigated-away previews cannot reopen after a late response. If applying has an uncertain result, inspect **Log** before trying a fresh preview; the client never automatically retries an action. Once an apply request has started, it must finish before resetting the demo. Cancellation is available before confirmation, and undo afterwards.

## Isolation contract

- `scripts/run_demo.py` sets a process-level `MAIL_SUMMARISER_DEMO=true` lock before importing the backend. An HTTP setting cannot disable it.
- The lock creates a new temporary database instead of opening the normal data directory. It ignores mailbox/provider configuration and credentials for effective settings. Existing mail databases are not read or changed.
- Summary generation returns deterministic local excerpts before any provider discovery, prompt generation, API-key resolution or network call.
- The HTTP boundary defaults to deny. Live connection tests, settings writes, email sending, model/runtime operations, dev tools and database admin routes are unavailable.
- The browser uses the current origin, ignoring saved backend addresses and saved API keys. The response policy allows connections only to that origin. Host/origin checks reject non-loopback and cross-origin requests.
- Actions require a five-minute, single-use preview token bound to the exact job, action, plan and safety state. Missing, expired, replayed and changed plans fail closed. Demo mutations and related reads are serialised within the single process.
- Samples and undo are in memory; the synthetic local index is in a dedicated temporary directory. Normal shutdown removes that directory. An abrupt OS/process termination can leave temporary synthetic files for normal OS cleanup. Nothing real is stored there.
- This is isolation of the supported demo routes, not an OS network sandbox. Do not import or call arbitrary backend internals as part of a demo.

The normal `backend.app:app` launch without this lock retains its existing live/account/provider behaviour. In that mode, **Sample Mailbox** alone is not the same as the isolated demo: configured summary providers may still be called. Existing live actions retain their prior API contracts; mandatory server-side preview tokens in this change apply to the locked demo only.

## Validation

```sh
python scripts/validate_demo_api.py
pytest -q
python scripts/validate_demo_ui.py --output demo-evidence
```

The API acceptance script runs in a fresh demo process, supplies deliberately conflicting synthetic environment settings and traps network/provider/SMTP calls before startup and through shutdown. Nineteen API tests include completed apply/undo/reset with failed index refresh. Nine mocked client-state checks exercise truthful load/view failure reporting, duplicate undo suppression and held successful/failed review/triage detail responses across reset. A confirmed reset immediately invalidates old selections while keeping pending/failure state explicit. It covers initial indexing, dry run, no-preview rejection, expiry, replay/concurrency, changed plans, apply, archive/resync, undo recovery and reset. The browser script uses the visible scoped-action controls, including real one-shot index faults injected into its CI-only server fixture without adding production routes. Its server traps outbound network/provider/SMTP calls. The script runs real Chromium against a synthetic local server and covers onboarding, evidence, preview/cancel, simulation, apply/undo, late responses, errors/retry and mobile controls.

The `Isolated synthetic demo` PR workflow retains only four small screenshots and a JSON check summary for seven days. Ordinary CI also runs the existing full tests/startup/browser regression. Local browser execution was unavailable in the implementation sandbox; CI evidence must be checked for the exact draft head before claiming browser acceptance.
